# z2r_autobench

Автотюнинг и автобенчмарк стратегий DPI-обхода для [z2r](https://github.com/AloofLibra/z4r)
(форк [zapret2](https://github.com/bol-van/zapret2)). Не подменяет z2r — работает
поверх него: перебирает стратегии по каждому профилю трафика, меряет надёжность
и подставляет лучшую в `locked.tsv`/`profile.lock`, либо делает то же самое
самостоятельно в фоне через systemd-демон.

## Быстрый старт

```bash
curl -O https://raw.githubusercontent.com/scp-oss/z2r_autobench/main/z0r && sh z0r
```

При первом запуске `z0r` сам:
- ставит z2r (ядро DPI-обхода), если его ещё нет — через официальный
  установщик автора (GitHub, при недоступности — зеркало `git.px.rkn.quest`);
- клонирует сам себя (полный `z2r_autobench`) в `/opt/z2r_autobench`;
- предлагает поставить фоновый демон автотестирования-автоподстройки —
  отказался, ничего страшного, предложит снова при следующем запуске;
- дальше открывает интерактивное меню.

Повторный запуск той же командой (или просто `sudo ./z0r` внутри
`/opt/z2r_autobench`) тихо подтягивает обновления из GitHub и сразу
открывает меню.

## Меню

```
=== Тест профилей ===
111) Тестировать все профили     — 1,2,3,4,5 полным тестом; 6 — из кэша; 7/8/9 — заглушки
  1) YT_TLS / 2) GV_TLS / 3) RKN_TLS / 4) DS_TLS / 5) YT_QUIC_UDP
  6) VOICE_UDP [бета]  7) GAMES_UDP [dev]  8) FB_TLS [dev]  9) FB_HTTP [dev]
     (можно выбрать несколько сразу: "1,3,4")

=== Подбор стратегии ===
 10) Тест конкретного домена
 21) Ручное переключение стратегии (профиль + номер вручную, без перебора)

=== z2r ===
 11) Запустить меню z2r (свежий curl+sh с GitHub, как вручную; при
     недоступности GitHub — резервный источник git.px.rkn.quest, как в
     install_z2r(); совсем без сети — уже установленная локальная копия)

=== Управление ===
 12) Zapret сервис [ON/OFF/NONE]        — статус, установка, перезапуск
 13) autotune-daemon [ON/OFF/NONE]      — фоновый автотюн
 14) Discord_bot [ON/OFF/NONE]          — голосовые тесты VOICE_UDP
 15) web_panel [dev]                    — заглушка, пока не реализовано
 22) Zenith [ON/OFF/NONE]               — автоподборщик-генератор стратегий (docker compose)

=== Удаление ===
 16-20) удалить z2r / autotune-daemon / Discord_bot / web_panel / сам автобенч
 23) удалить Zenith
999) удалить всё разом (каждый компонент со своим подтверждением)

  0) Выход
```

Также доступны CLI-флаги без меню: `--profile N`, `--profiles 1,3,4`, `--all`,
`--domain example.com [--apply]`, `--install-service`, `--install-z2r`,
`--uninstall`.

## Профили

| # | Профиль | Протокол | Статус |
|---|---|---|---|
| 1 | YT_TLS | tls+http | рабочий |
| 2 | GV_TLS (Googlevideo) | tls | рабочий, тестовый URL резолвится через `yt-dlp` |
| 3 | RKN_TLS | tls | рабочий |
| 4 | DS_TLS (Discord) | tls | рабочий |
| 5 | YT_QUIC_UDP | udp/QUIC | рабочий, нужен `aioquic` |
| 6 | VOICE_UDP | udp | бета — тест только через Discord-бота (`zapret-voice-bot`), в демон не встроен |
| 7 | GAMES_UDP | udp | тестер не реализован |
| 8 | FB_TLS | tls | не работает — тестовый домен (`rutracker.org`) уже входит в `TCP_RKN_list.txt`, трафик уходит через профиль 3, а не в fallback-блок |
| 9 | FB_HTTP | http | та же причина, что и у 8 |

Профили 2 и 5 резолвят тестовый URL через `yt-dlp`, а он ходит на
`youtube.com` через ЖИВУЮ стратегию профиля 1 — если у профиля 1 в моменте
сломанная стратегия, тесты 2/5 могут провалиться со 100% не из-за себя, а
из-за резолвинга. `z0r` знает про эту зависимость: при выборочном/полном
тесте, если запрошен 2 и/или 5, профиль 1 тестируется первым, и его лучшая
стратегия применяется сразу, без вопроса (в отличие от остальных профилей,
где применение всегда спрашивается). 4/6 такой явной зависимости пока не
получили — отдельная история.

Профили 8/9 отключены по умолчанию (`SKIP_PROFILES=8 9` в
`autotune-daemon.service`) до тех пор, пока не найдётся тестовый домен вне
всех хостлистов z2r.

Живая проверка на NETH-4 (2026-08-04): `rutracker.org/forum/index.php`
открывается нормально через профиль 3 (RKN_TLS, стратегия 1) — это
подтверждает, что домен именно перехватывается профилем 3 раньше, чем
доходит до fallback-блока (8/9), а не то, что он в принципе недоступен.
Перед выбором замены — проверять `grep -ril "$d" /opt/zapret2/extra_strats/*.txt /opt/zapret2/lists/*.txt`,
чтобы убедиться, что новый тестовый домен не входит вообще ни в один
хостлист z2r.

## Компоненты

- **`z0r`** — единая точка входа: bootstrap + меню (см. выше).
- **`autotune_daemon.sh`** / **`autotune-daemon.service`** — фоновый демон:
  health-check по каждому профилю, точечный ретюн при `FAIL_THRESHOLD`
  провалов подряд, backoff после ретюна без единой рабочей стратегии,
  singleton-lock, dependency-check (`yt-dlp`/`aioquic`), лог-ротация.
- **`rank_strategies.sh`** / **`rank_quic.sh`** — многопроходный перебор
  стратегий одного профиля с усреднением (отличает стабильно рабочие
  стратегии от разового сетевого шума). Флаг `--funnel` (по умолчанию у
  `z0r` и у `autotune_daemon.sh`) экономит запросы: каждый следующий проход
  гоняет только тех кандидатов, кто хоть раз сработал в предыдущем, а не
  все стратегии заново — старый честный режим (перебор всех стратегий на
  каждом проходе) остаётся доступен без флага.
  `rank_quic.sh` по умолчанию меняет тестовое видео (и тем самым
  googlevideo-эдж) на каждый проход — CDN стабильно матчит один и тот же
  эдж на пару (video_id, наш IP), поэтому просто дёргать yt-dlp заново на
  тот же ролик каждый раз не даёт разнообразия (проверено на NETH-4: 6
  проходов подряд — один и тот же эдж). ISP обычно блокирует конкретные
  CDN-узлы, а не домен целиком, так что без ротации видео тест рискует
  залипнуть на незаблокированном эдже и ложно показать "100% у всех
  стратегий". `--host HOST [--path PATH]` фиксирует конкретный эдж вручную
  — полезно, чтобы прогнать тест именно против узла, на который попадает
  проблемное устройство.
  `rank_strategies.sh` по умолчанию исключает из подбора для профилей
  1/2/3/8 стратегии 31,32,33,34,35,36,38,39,41,42 — они используют
  `tls_client_hello_clone:blob=clone_deepseek|clone_hcaptcha`, а этот blob
  не статический файл, а захватывается ДИНАМИЧЕСКИ из живого TLS-хендшейка
  к chat.deepseek.com/hcaptcha.com. Если на машине никто и никогда не
  заходил на эти домены через nfqws2 — blob навсегда "unavailable", и
  стратегия молча пропускает пакеты БЕЗ обхода вообще (может даже пройти
  тест, если ISP в моменте не блокирует конкретный URL, и попасть в топ
  рейтинга как "рабочая", хотя не делает ничего — так и было один раз
  вживую на NETH-4, strategy=36 сломала работавший доступ). `--include-
  clone-strategies` возвращает старое поведение.
- **`cross_device_tune.sh`** — хост-тест находит только "работает ли с
  сервера", но по опыту не все хост-рабочие стратегии реально работают на
  ТВ/мобильном (разные клиенты ведут себя по-разному даже на одном
  канале). Берёт кандидатов из `ORDERED_SUCCESS` предыдущего
  `rank_strategies.sh`/`rank_quic.sh` (или свой список через
  `--candidates`), применяет по одной и спрашивает "работает на ПК/моб/ТВ?"
  — ответы копятся в `logs/cross_device_profile_<N>.tsv` между запусками
  (можно продолжить позже). В конце — отчёт, какие стратегии универсальны
  (да everywhere), какие частично. `--report` — только отчёт по уже
  накопленным данным, без нового обхода.
- **`blob_tune.sh`** — отдельный дорогой цикл: перебор fake-TLS
  ClientHello blob'ов (требует рестарта `nfqws2` на каждый blob, в отличие
  от обычной смены стратегии).
- **`night_tune.sh`** / **`exhaustive_tune.sh`** — полный ночной прогон
  всех профилей.
- **`test_custom_domain.sh`** — подбор стратегии под произвольный домен.
- **`set_strategy_cli.sh`** — тонкий CLI-мост `set`/`get`/`max` для
  внешних вызывающих (используется, например, Discord-ботом).
- **`z2r_autobench_lib.sh`** — общая библиотека (сорсит `config.sh`,
  `orchestra_state.sh`, `netcheck.sh` из самого z2r).
- **`z2r-test-voice-bot.service`** — systemd-юнит для
  [`z2r_test-voice-bot`](https://github.com/scp-oss/z2r_test-voice-bot)
  (отдельный репозиторий, не входит в этот; клонируется по требованию
  через пункт 14 меню в `zapret-voice-bot/`/`z2r_test-voice-bot/` внутри
  `/opt/z2r_autobench`, у самого бота своего юнита нет).
- **[`Zenith`](https://github.com/scp-oss/zenith)** — автоподборщик-
  генератор стратегий (мутации/скрещивание параметров, не просто перебор
  готового списка). Тоже отдельный репозиторий, не входит в этот;
  клонируется по требованию через пункт 22 меню в `Zenith/` внутри
  `/opt/z2r_autobench`, управляется через `docker compose` (без systemd).
  Найденные рабочие стратегии применяет тем же `set_strategy_cli.sh`, что
  и Discord-бот — z2r_autobench остаётся единственным путём к живому
  `/opt/zapret2`.

## Требования

- z2r (ставится через пункт 12 меню, если ещё не стоит).
- `yt-dlp` — для профиля 2 и резолва URL профиля 5.
- `aioquic` — для профиля 5 (QUIC).
- `bash` — `z0r` сам себя перезапускает под bash и ставит его при
  необходимости, даже если запущен через голый `sh`.

Отсутствие `yt-dlp`/`aioquic` не ломает демон — он сам это определяет и
временно пропускает зависящие профили, автоматически возвращая их в
работу, как только зависимость появится.

## Известные ограничения

- FB_TLS/FB_HTTP (см. таблицу выше) — нужен новый тестовый домен.
- VOICE_UDP не автотестируется демоном — только вручную через Discord-бота.
- GAMES_UDP (профиль 7) и web_panel — не реализованы, чистые заглушки.
- `zapret-voice-bot` README ссылается на `config/strategies.example.yaml`,
  которого в репозитории бота нет — писать `config/strategies.yaml`
  придётся с нуля по формату из README бота.
