# debug_capture.sh — временная запись трафика клиентов для отладки обхода

Когда у пользователя что-то не работает (YouTube в приложении, фото в Instagram, голос),
запишите его трафик на несколько минут и посмотрите сводку: какие домены (SNI) он открывал,
сколько длилось рукопожатие, где сервер не ответил, где были сбросы.

## Какой режим выбрать
| Как подключён клиент | Команда |
|---|---|
| Xray / 3x-ui (VLESS и т.п.) — сервер сам открывает соединения | `debug_capture.sh start --cgroup system.slice/x-ui.service --port 443 --minutes 5` |
| AmneziaWG / WireGuard (транзит через интерфейс) | `debug_capture.sh start --iface amn0 --client 172.29.172.N --minutes 5` |
| Любой трафик на внешнем интерфейсе | `debug_capture.sh start --iface eno2 --port 443` (в записи будут и фейки zapret) |

`--cgroup` копирует пакеты сервиса **до** zapret (TEE в mangle OUTPUT на временный dummy-интерфейс),
поэтому в записи нет подделок nfqws2 — только то, что реально отправлял и получал клиент.

## Дальше
```
debug_capture.sh status                # что пишется
debug_capture.sh stop [ID]             # остановить
debug_capture.sh analyze ID            # сводка (ставит tshark при первом запуске)
debug_capture.sh list | purge --days 3 # файлы / удалить старые
```
Файлы: `/var/lib/z2r-debug/` (только root), их можно открыть в Wireshark.

Безопасность: автостоп (по умолчанию 10 мин, максимум 60), кольцевой буфер 5×50 МБ, snaplen 2048.
Это трафик пользователей — записывайте коротко и удаляйте после разбора.

Пример (NETH-4, 2026-11-13): запись Xray показала, что фото Instagram идут с 31.13.72.53 и
157.240.205.63 — после добавления 157.240.0.0/16 в перехват Meta все 32/32 соединения CDN прошли.
